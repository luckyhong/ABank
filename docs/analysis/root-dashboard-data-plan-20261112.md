# 启动根页面数据完善与公开API评估

评估日期：2026-11-12（America/Los_Angeles）。代码基线main@e17c143，与ABank/main一致；本轮分析不修改App业务、不接入新服务。接手前3处配置差异及.impeccable本地产物保留。

## 判断

建议采用“本地业务数据联动 + 公开内容和参考行情 + 稳定缓存”。优先把已有Store的数据带到根页面，再引入少量公开数据，能够兼顾可信度、离线展示和纯前端项目的维护成本。

已确认37笔交易保持原始日期和金额；不能为了根页看起来每天有变化自动生成工资、消费或还款。真实感来自一致的时间、状态、来源和跨页关联，日内反复启动应得到稳定结果。

## 如何让本地数据更自然

1. 统一根页聚合层：从Ledger、Benefits、Customer、消息和城市读取页面快照；现有MockDataProvider可逐步退到初始内容/布局配置。刷新时只更新变化区域，保留滚动位置、筛选和轮播选择。
2. 待办有业务条件：未签到→签到入口，已签到→连续天数；缴费后移除待缴费；存款到期后显示支取；消息已读后同步角标。日期推进产生计划与待办，不自动声称交易已经成功。
3. 统一活动模型：稳定ID、开始/结束时间、城市、适用等级、关联权益ID、图片资源、详情路由。领取资格与商品优惠使用同一规则；过期活动退出默认推荐，不能仅把旧文案日期改成今天。
4. 稳定场景：若需要更丰富的月份或消费分布，另建独立场景账本；固定种子与场景业务日、一次初始化并持久化。每次启动重新随机金额、重复发放积分或覆盖原37笔均不采用。
5. 每条公开数据保留观察时间asOf、抓取时间fetchedAt、来源、单位、币种和缓存状态；网络失败时显示上次有效数据及日期。首次无数据就显示可解释空态/有日期的本地参考，不能假装刚刚更新。
6. 同一产品目录管理名称、风险、期限和数值口径。实际基金净值、国际金价和本地理财年化估算分开；原有订单收益规则不能因换了根页行情而静默改变。

## 启动和刷新建议

- 首屏同步展示本地账本/权益和上次有效内容，不等待行情或RSS网络完成；避免为模拟加载添加固定等待时间。
- 后台异步刷新公开内容，同一来源请求合并、取消无用请求；首页/财富/资讯共用结果。
- 建议起始缓存策略：RSS 15–30分钟，日更汇率按来源下一更新时间/营业日刷新，金价按实际额度低频，天气30–60分钟。均为拟定策略，不宣称当前已实现。
- 观察日期与抓取日期分别保存；周末沿用上一发布日的汇率，不能将今天抓到的旧报价标为今天交易价。
- UI展示“1美元≈x人民币”或“100美元≈x人民币”；金价写明人民币/克或美元/金衡盎司。两种口径转换须保留两项原始日期，页面统一说明参考来源。
- 外部行情与个人账本隔离：根页报价变化不重算已确认历史交易金额，也不直接驱动本地存款/贷款实际扣款。
