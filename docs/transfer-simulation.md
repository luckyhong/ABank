# M1：本地转账模拟闭环

## 当前能力与边界

账号转账、手机号转账、演示伙伴选择、付款账户选择、金额/附言输入、确认、模拟结果、记录筛选和详情已接通。成功记录可进入现有收支详情，返回后余额、明细、收支与资产从同一账本刷新。

所有操作只作用于本地演示数据，没有银行网络请求、短信验证码、支付密码或真实手机号绑定查询。手机号由用户填写演示姓名后直接参与模拟，不声称验证了真实收款人。表单、确认和结果缺少真实页面截图，采用项目现有字体、白色卡片和青绿色样式设计；原转账首页继续沿用已有参考资源。

转账设置当前仅查看单笔/每日限额及零手续费。预约转账、多人转账、信用卡还款、转账撤销等功能不属于本轮；安全设置编辑在 M4 完善，电子回单在 M2 实现。

## 数据与接口

- `TransferDraft` 是仅在内存使用的表单，不参与持久化。输入金额转换为 `Int64` 分；完整收款账号/手机号仅存在于草稿。
- `TransferRecord` 保存请求 ID、付款账户 ID/脱敏标签、转账方式、收款人、银行、脱敏收款标识、金额分、附言、北京时间、成功/失败及关联流水 ID。
- `FinanceLedgerRecord.transferRecords` 与原 accounts/transactions 共用 `abank.financeLedger.record.v8`。旧 JSON 缺少新字段时解码为空数组，不换 key、不重建历史。
- `validateTransfer(_:)` 用于确认前检查；`submitTransfer(draft:requestID:)` 再按最新余额、日期和限额检查。主 actor 同步执行，提交过程没有 await。
- 同一请求 ID 无论再次点击还是重启后重试，均返回已保存结果，不生成第二条记录/流水。请求 ID 表示同一次不可变确认；修改草稿或重新发起失败交易须生成新 ID，不能复用旧 ID 来修改已保存交易。
- `TransferMoney` 集中处理输入解析及与旧 Double 账本的转换。新金额允许正数、最多两位小数；逗号、指数、负数及超长数字拒绝。未全面迁移旧账本的 Double 字段。

## 提交流程与失败处理

1. 草稿确认不写数据；返回修改或取消不会扣款。
2. 点击确认后按钮禁用，短暂展示“正在处理模拟转账”；阻止重复确认和交互返回。
3. 读取最新根记录，查找相同请求 ID；已存在则直接返回。
4. 校验付款账户、收款人、金额、附言、同账户、余额和限额。
5. 成功时在同一根快照中追加一条 `transfer_out` 流水及成功记录，重算余额并更新时间戳，一次编码/写入后通知页面。
6. 可注入的模拟失败场景只保存失败记录，不生成扣款流水。正常运行默认成功，不随机决定财务结果。
7. 编码或注入写入失败返回错误，不展示成功；旧持久化字节保持原样。UserDefaults 是本地演示存储，不提供银行级断电事务或同步落盘保证。
8. 已存在但无法读取的账本不被静默覆盖；提交返回明确错误。普通读取的降级展示也不会覆盖损坏字节。

处理中只是一种 UI 状态，不单独保存 pending 记录。若在实际提交前退出，没有交易；若提交已保存但结果页尚未出现，重启后可在记录中查询。

## 校验、历史与联动

- 初始演示限额：单笔 50,000 元，每个北京时间自然日全付款账户累计 200,000 元。仅累计本机成功转账记录，失败记录不占用额度；旧种子流水不冒充本机新提交记录。
- 账号输入 16–19 位数字，允许去除空白；手机号为 11 位演示号码。收款人 1–40 字、附言最多 60 字。
- 现有预设伙伴按稳定 ID 解析；自己已知的默认借记卡不能转给同一付款账户。该校验基于项目现有演示卡与关联 ID，不声称识别任意真实卡号的归属。
- 历史记录可使用已保存的脱敏目的地再次模拟转账，无需伪造完整账号；已保存伙伴信息以本地记录为准。
- 最近伙伴从成功记录更新，保留原首页多账户展开能力；仅成功交易进入最近伙伴。
- 同秒记录按追加顺序显示，流水余额重算也保留同秒追加顺序，避免随机 UUID 改变交易先后。
- 新流水参与账户余额及当前月收支，多个账户的资产分类金额汇总全部账户。收支详情的分类/备注/是否计入收支可继续编辑，但转账记录保留原始确认信息。

## 检查与交接

数据检查入口：

```sh
scripts/check_banking_data.sh
```

此脚本在临时目录编译并分别执行 M0 与 M1 的独立检查，使用独立 UserDefaults suite，不依赖测试 Target 或正常 App 的账本。涵盖旧 JSON、整数分输入、同请求多任务提交、重启幂等、同秒排序、多付款账户、恰好用尽余额、余额变化后重校验、单笔/每日限额、北京时间午夜、失败/重试、脱敏历史、取消、写入/编码失败及损坏数据保留。

构建命令沿用 [开发计划](development-plan.md)。UI 验证使用独立包，程序触发入口、按钮、回调和通知；截图和检查结果保留在本地 `artifacts/abc-resources/verification/m1-*`。完整手指交互、真实原版子页逐像素对照不在已验证范围内。临时 QA 入口交付前移除。

M2 已基于 `TransferRecord.transactionID` 与既有流水派生账单分析、交易搜索和带模拟标记的电子回单，并把收支分组改为完整日期，见 [M2 说明](bill-receipt.md)。
