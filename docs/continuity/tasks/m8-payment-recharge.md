## 裁定（偏离计划处）
- 功能目录检查里“计划中不记录最近使用”的用例原用 `.mobileRecharge`（现已可用），改用仍为计划中的 `.charity`。
- 话费券与账本两个 key 无法一次写入：先 `useCoupon` 再写账本，写入失败释放券；两步之间进程被杀或释放也失败时，最坏结果是多用掉一张券，不会多扣款（规格 §2 已接受）。
- 审查修复：提交接口新增可选 `expectedPaidInCents`/`expectedPeriod`/`expectedAmountInCents`，弹窗期间券失效或跨月则抛 `amountChanged` 而不是静默改扣。
- 手机号规范化只去空格与连字符；M4 转账限额与小额免密不套用，面额只有固定档位。

## 延后 Minor（审查）
- “充值记录”“缴费记录”入口打开的订单页默认在“全部”而非“充值缴费”筛选（规格 §4 偏差，需给订单页加初始筛选）。
- 手机充值页每次刷新会重建输入行，输入过程中点面额或回前台会收起键盘。
- 充值成功后返回会回到可再次提交的确认页（`requestID` 已重新生成），可改为替换为详情页。
- 手机号规范化不处理粘贴带来的不间断空格或方向标记字符。
- `validateMobileRecharge` 目前未被使用。
- `PaymentFlowViewController` 与 `BenefitsFlowViewController` 有重复的辅助方法，可抽共享基类。
- 账户明细里缴费流水使用通用箭头图标，可为 `mobile_recharge`/`life_payment` 映射专用图标。
- “我的订单”选中“充值缴费”后筛选条回到最左，选中项被裁切（既有 `BranchChipBar` 行为）。
- 既有 M6 卡券详情仍提供“模拟使用”，话费券可不抵扣被直接消耗（产品取舍，未改）。
