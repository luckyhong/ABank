# M9b 贷款待办、进度、结清证明与提前还款设计

日期：2026-11-07。基线：`main@8ba6d49`（M9a 已合并并推送），分支 `feat/m9b-loan`。对应 [开发计划](../../development-plan.md) 阶段 M9 的贷款部分。

## 1. 目标与已确认决策

**目标**：把“我的贷款”页四个宫格入口、右上角“历史贷款”和提前还款提交从只弹提示做成可演示的本地功能。提前还款是唯一改动数据的操作：成功才同时更新借记卡余额、未还本金、流水和记录，失败全部不变。

用户已确认：

| 议题 | 决策 |
|---|---|
| 提前还款 | 部分提前还款，可选“缩短期限 / 减少月供”；只还本金，不计息、不收违约金；本期不做全额结清 |
| 进度查询 | 贷款业务办理进度：提前还款、结清证明申请自动生成记录，另含种子历史贷款申请；可看时间线详情 |
| 待办任务 | 按账本自动生成提醒，点击跳对应页面，条件消失即消失；不另存完成状态 |
| 历史贷款 / 续贷 | 历史贷款展示种子已结清贷款并可开结清证明；贷款续贷只做说明空态，不做办理流程 |
| 存储方案 | 方案 A：扩展现有账本 `FinanceLedgerRecord`，提前还款一次原子写入 |
| 视觉参考 | 无原版页面截图，按现有贷款页风格设计，交接中标注“待截图校准” |

**验收标准**

1. 宫格“待办任务”“进度查询”“贷款续贷”“结清证明”与导航“历史贷款”都进入对应页面，不再弹提示。
2. 提前还款输入合法金额并确认后，借记卡余额减少该金额，住房贷款未还本金减少同额；按所选方式更新每期还款或剩余期数与到期日；新增一笔流水和一条办理记录；结果页展示前后对比。
3. 提前还款后，我的贷款、贷款详情、下月应还、还款计划、还款明细、使用记录、资产负债、账户明细、本月收支全部显示一致的新值；重启后保持。
4. 金额不合规、余额不足、确认期间数据变化、账本损坏或写入失败时不扣款、不改本金、不生成流水或记录，并给出对应提示。
5. 同一 `requestID` 重复提交只返回首次记录。
6. 结清证明对每笔已结清贷款只生成一条申请记录，可查看、分享模拟证明；待办“结清证明待开具”随之消失。
7. M9a 的两项交易权限关闭时不影响提前还款。

## 2. 方案选择

- **A（采用）扩展账本**：贷款状态与办理记录都在 `FinanceLedgerRecord`，扣款、本金、流水、记录一次 `persist`。与 M7 理财、M8 缴费同一模式。
- B 独立 `LoanStore`：余额与本金分属两个存储，无法原子写入，违背“不另造互不一致的余额”，不采用。
- C 只改本金、计划仍写死：还款计划和下月应还与新本金不一致，不满足验收 3，不采用。

## 3. 数据与规则

### 3.2 等额本息计算（`LoanAmortization`，内部以分计算）

- 月利率 `r = annualRatePercent / 100 / 12`；每期利息 = 本金 × r，四舍五入到分；每期本金 = 每期还款额 − 利息；最后一期本金为剩余本金、还款额相应调整，余额精确归零。
- 校验：本金 330,318.93、每期 2,934.91 → 第 107 期利息 880.85、本金 2,054.06、余额 328,264.87，第 108 期 875.37 / 2,059.54 / 326,205.33，与现有种子一致；剩余期数 134，末期为第 240 期。
- 还款计划：日期早于 `nextDueDate` 的期次保留现有种子；从 `nextDueDate` / `nextPeriod` 起按公式由当前未还本金生成，期间按月递增（每月 9 日）。
- **缩短期限**：每期还款额不变，理论期数 x = −ln(1 − P·r/A) / ln(1 + r)；x 小数部分 < 0.01 时取 floor(x)（尾差并入末期），否则取 ceil(x)。种子 x≈134.0004 → 134 期，末期还款 2,935.87。
- **减少月供**：剩余期数不变，每期还款额 = P·r·(1+r)^n / ((1+r)^n − 1)，四舍五入到分。
- 到期日 = 末期还款日（`nextDueDate` 后推 剩余期数 − 1 个月）的前一天，更新 `maturityDateText`（`yyyy年M月d日`），种子为 2037年10月8日；`expiryDate`（合同有效期）不变。提前还款页“贷款到期日”改读此值。
- 时钟不自动推进还款：不按真实日期生成月供扣款，`nextDueDate` 保持；新记录时间取当前北京时间（`BankingDateContext`）。

### 3.3 提前还款规则（`LoanRules`）

- 金额：≥ 100.00 元；最多两位小数；≤ 付款账户余额；**必须小于**未还本金。
- 付款账户为默认借记卡 `acct_8472`；显示用 `cardLabel`（含别名）。
- 校验顺序：贷款存在且未结清 → 金额格式与下限 → 小于本金 → 余额充足 → 预期值一致。全部在写入前。
- 不受 M9a 交易权限（手机银行转账、网上支付）影响。

### 3.4 错误（`LoanError`）

| case | 文案 |
|---|---|
| `amountInvalid` | 提前还款金额最低 100 元，最多两位小数 |
| `amountNotLessThanPrincipal` | 提前还款金额须小于未还本金 |
| `insufficientBalance` | 账户余额不足 |
| `contractUnavailable` | 贷款不存在或已结清 |
| `changed` | 信息已变化，请重新确认 |
| `corruptLedger` | 账本数据异常，暂不能办理 |
| `persistence` | 本地保存失败，请重试 |
| `invalidRequest` | 请求无效，请重试 |

### 3.5 写入（`FinanceLedgerStore+Loan.swift`）

- `previewPrepayment(contractID:amountInCents:method:) throws -> LoanPrepaymentPreview`：只读试算，返回前后值。
- `submitPrepayment(contractID:amountInCents:method:requestID:expected:) throws -> LoanServiceRecord`：
  - `requestID` 为空或超过 100 字符 → `invalidRequest`；严格读取账本（损坏 → `corruptLedger`，不覆盖）。
  - 同 `requestID` 已有记录则直接返回。
  - 重新试算；`expected`（确认时的本金、余额、每期还款额/期数）不一致 → `changed`。
  - 一次原子 `persist`：扣借记卡余额；追加流水（标题“提前还款-个人住房贷款”，类别新增 `loan_repay`“还贷款”归入支出组，计入本月收支）；更新合同本金、每期还款额/剩余期数、到期日；追加办理记录；更新 `dataTimestamp`。失败 → `persistence`，内存与存储都不变。
- `requestSettlementCertificate(loanID:requestID:) throws -> LoanServiceRecord`：贷款须在历史目录且已结清；同一贷款已有证明记录则直接返回；写入失败 → `persistence`。
- 读取：`loanServiceRecords()`（新→旧）、`loanTasks()`、`settlementCertificate(loanID:)`。

### 3.6 待办任务（派生，`LoanTasks`）

| 任务 | 条件 | 文案 | 跳转 |
|---|---|---|---|
| 还款提醒 | 存在未结清贷款 | “MM-dd 应还 x 元” | 下月应还 |
| 余额不足 | 借记卡余额 < 下期每期还款额合计 | “账户余额不足以支付下期还款，还差 x 元” | 我的账户 |
| 结清证明待开具 | 已结清贷款无证明记录 | “x 已结清，可申请结清证明” | 结清证明 |

## 4. 页面与交互

### 4.1 入口

- 我的贷款宫格：待办任务、进度查询、贷款续贷、结清证明 → 各自新页面；导航“历史贷款” → 历史贷款页。
- 贷款详情“提前还款” → 改造后的提前还款页。

### 4.2 提前还款页（改造现有页）

- 保留现有信息行；新增付款账户（`cardLabel`）与可用余额、金额输入、还款方式切换（缩短期限 / 减少月供，默认缩短期限）、试算区（还款后未还本金；新每期还款额或新剩余期数与到期日）。
- 输入即时试算；不合规时行内提示并禁用按钮。
- 点“提前还款”弹确认（金额、方式、付款账户）→ 带试算预期值提交 → 成功推入结果页并从导航栈移除表单页；`changed` 时留在原页刷新试算并提示。

### 4.3 提前还款结果页（新）

成功横幅（标注“模拟交易”）；金额、方式、未还本金前→后、每期还款额或剩余期数前→后、新到期日、付款账户、时间、业务编号；按钮“查看办理进度”“返回我的贷款”。

### 4.4 待办任务页（新）

按 3.6 列表展示，每项带说明与“去处理”；空态“暂无待办任务”。

### 4.5 进度查询页 → 办理详情页（新）

- 列表新→旧：账本办理记录 + 种子历史申请；每行业务名称、贷款名称、时间、状态“已办结/已放款”。
- 详情：时间线“提交 → 受理 → 办结”（演示记录三步同一时间；种子申请按其日期），下方业务字段；提前还款详情展示与结果页相同的前后值。

### 4.6 结清证明页 → 证明详情页（新）

- 列表为历史目录中已结清贷款；无证明时按钮“申请开具”，有则“查看证明”。申请幂等，重复点击直接打开已有证明。
- 证明详情：借款人（`CustomerInfoStore.shared.load().name` 经 `AccountHolderName.masked` 脱敏，如“韩*宏”，与 M9a 分享页同源）、合同号、贷款金额、期限、结清日、证明编号、“模拟证明，仅供演示”水印与印章样式；“分享”以文本调用系统分享面板。

### 4.7 历史贷款页（新）

列出已结清贷款（名称、金额、期限、结清日）；点击打开对应结清证明详情，未申请则提示先申请并跳结清证明页。

### 4.8 贷款续贷页（新）

空态“暂无可续贷的贷款”，列出续贷条件（贷款临近到期、无逾期记录、符合准入要求）；按钮“返回”。

### 4.9 联动的现有页面

- 我的贷款汇总与合同卡：未还本金、到期日。
- 下月应还：金额改读合同 `installmentAmount`，日期读 `nextDueDate`（替换写死的 2,934.91 / 2026-09-09）。
- 还款计划页签：未来期次按 3.2 生成；还款明细页签与使用记录：并入提前还款记录（本金=金额，利息/罚息为 0）。
- 资产负债、借记卡余额、账户明细、本月收支：经账本自动更新。

## 5. 测试与验收

### 5.1 数据检查（新增 `scripts/check_loan.swift`，加入 `check_banking_data.sh` 第 11 组）

- 等额本息：种子本金复现第 107 期 880.85 / 2,054.06 / 328,264.87；剩余 134 期；缩短期限与减少月供的固定样例值；末期余额归零。
- 金额：100、100.5 通过；99.99、100.001、等于本金、超过余额拒绝并给出对应错误。
- 成功提前还款：余额、本金、每期还款额/期数、到期日按预期变化；新增 1 条流水（`loan_repay`，计入本月支出）与 1 条办理记录；使用记录、还款明细含新记录；下月应还金额变化（减少月供时）。
- 幂等：同 `requestID` 返回同一记录，账本不再变化。
- 失败不变：余额不足、预期值变化、账本损坏（不覆盖）、写入失败（`dataWriter` 注入）。
- 兼容：无新字段的旧账本解码为默认值；资产负债与我的贷款汇总不含历史贷款。
- 待办：初始含“余额不足”；余额足够后消失；申请结清证明后“待开具”消失。
- 结清证明：申请幂等；户名脱敏正确。
- 权限：M9a 两项权限全关时提前还款仍成功。
